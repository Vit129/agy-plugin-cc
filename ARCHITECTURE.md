# agent-bridge — System Architecture

> Status: **active** (v1.6.3). Companion to `README.md` and `CLAUDE.md`.

## Constraints & Objectives

- **Ecosystem Bridging:** Bridges Google Antigravity (agy) CLI and IDE developer workflows into Claude Code and OpenAI Codex CLI from one plugin tree, without modifying either host's internals.
- **Bridge, not engine:** heavy work (reading documents, browsing, transcription, image generation) belongs to agy. New capabilities start as a command `.md` plus prompt; runtime code is added only when the companion must do something itself (job tracking, test gates, usage).
- **Job Lifecycle & Tracking:** Long-running background jobs executed via `agy` must be tracked with robust status recovery and stdout/stderr logging.
- **Graceful Degradation:** Fails gracefully with actionable setup instructions if the local `agy` binary is unauthenticated or not installed on PATH.

## Subsystems

1. **Host manifests & surfaces:**
   - Claude Code: `plugins/agy/.claude-plugin/plugin.json`, slash commands in `commands/`, the `agy-rescue` agent, hooks in `hooks/hooks.json`. Marketplace: `.claude-plugin/marketplace.json` at the repo root.
   - Codex: `plugins/agy/.codex-plugin/plugin.json`, the `$agy` skill in `codex/skills/agy/`, hooks in `plugins/agy/hooks.json`. Marketplace: `.agents/plugins/marketplace.json`.
   - The host is detected at runtime from `CLAUDECODE` (set by Claude Code); `.codex-plugin/` always exists, so it cannot be used for detection.
   - Release scripts bump and check every manifest, including the nested `plugins/agy` ones the marketplaces install from.
2. **Execution Wrapper (`scripts/`, `skills/`):**
   - Dispatches one-shot or multi-turn prompt requests to `agy`, capturing output artifacts and providing session resumption.
   - `scripts/agy-companion.mjs` is the entry point only: usage text and the subcommand switch. Hooks and slash commands call it by this path, so it keeps its name.
   - `scripts/features/<feature>.mjs` holds one feature each (`task`, `review`, `handoff`, `jobs`, `setup`, `info`); `features/shared.mjs` holds CLI plumbing used by several features (argument parsing, output, job creation, agy option validation).
   - `scripts/lib/` holds logic and adapters with no CLI concerns (agy process, git, state, rendering, hand-off loop, usage parsing); tests import these directly.
   - A new subcommand gets its own `features/<name>.mjs` and one `case` in the entry switch; do not grow the entry file or `shared.mjs` with feature code.
   - agy is called with `--output-format json`; `lib/usage.mjs` unwraps the reply and records token usage on the job and in `usage.jsonl` in the state dir.
4. **Skills (one source, two hosts):**
   - `skills/` is shared and loaded by both hosts; edit shared guidance and the flag list (`agy-companion-reference`) there only.
   - `cc/skills/` is Claude-only (added through the Claude manifest's `skills`, which supplements the default scan); `codex/skills/` is Codex-only (the Codex manifest lists `./skills/` and `./codex/skills/` because its list replaces the default).
   - A skill name must be unique per host; `tests/skills-layout.test.mjs` enforces the layout.
5. **Review & Stop-Time Gate:**
   - Integrates session-aware review gates to verify code changes generated by Antigravity prior to session termination.

## Agent Usage

`apps/agent-usage/` owns the loopback HTTP server, browser assets, quota alerts, and model usage aggregation. `npm run dashboard` starts or reuses the listener. The server reads enabled providers on a shared configurable cadence and skips a CLI probe when all of its status-line windows are live. It publishes Claude and Gemini CLI samples as separate files in the existing shared quota cache and reads only metrics from enabled providers' local transcripts. Provider switches and alert state persist outside the repository. The server can process quota updates with the browser closed. Scheduled checks record fresh or stale evidence separately from provider-reported reset times.

The setup plan delegates launcher and LaunchAgent installation to the Agent Usage CLI and menu bar build. LaunchAgents are rendered with the current clone, home and label prefix. The server and menu bar start at login, and the reset agent checks persisted schedule times. The startup and install entrypoints inspect Git worktree metadata before starting or changing persistent state. The browser renders the shared provider path data directly, and the menu bar build embeds the same data for AppKit template rendering.

The companions use the same pure Auto-Route policy with fresh cached 5h/7d values and Agent Usage thresholds. Claude-side routing runs before agy discovery or job creation. The dashboard reads both directions from the shared cache and updates the shared `route-off` marker. The CLI probe reports Claude panel parsing failures as explicit row errors and logs changes to the failure reason.

Named profiles scope native samples, transcript reads, and alerts by provider and account. The account inventory reads each provider's local identity file. Terminal sign-in creates private CLI homes under the state directory and a marker identifies homes Agent Usage can remove. Signed-in managed homes join the monitored profiles automatically. The inherited CLI environment feeds the shared Auto-Route cache.

The serialized refresh checks Codex credit status at reminder boundaries and saves delivery markers in the local alerts file. Claude Full reset expiry and manual used state are stored in Agent Usage settings by CLI account UUID. A fresh matching entry in the read-only Claude CLI status cache overrides the manual state. Both credits use the same 24-hour and 2-hour reminder planner. Recent transcript modification times report provider activity without parsing the logs. The loopback quota API supplies both clients with quota rows, active providers and account identities. Claude and Codex plan labels come from their existing local account metadata when recognized. The AppKit status title uses the quota thresholds and title-provider preferences from the snapshot. The SwiftUI popover uses the Foundation-only pace calculation. Older servers can omit title preferences and plan metadata.

The Claude Code and Antigravity plugin startup hooks check the saved provider switch through `agent-usage on-provider-start` before starting the server. Manual startup and scheduled checks use their own entry points.

## Layers (Dev + QA pattern)

Standard: `dev-qa-pattern` (BE = logic and data with no UI; FE = what the user sees or touches). Tags are `[BE|FE-BL|UT|IT]`, test ids `[TC-<AREA>-NN]` and unique.

| Layer | Folder / file | Notes |
|---|---|---|
| BE core (pure rules) | `apps/agent-usage/quota.mjs`, `provider-quota.mjs`, `reset-credits.mjs`, `view-model.mjs`, `plugins/agy/scripts/lib/quota-route.mjs`, `menubar/QuotaPace.swift`, `StatusTitle.swift`, `UsageSnapshot.swift` | No DOM. `view-model.mjs` owns every dashboard rule (alerts, levels, route status, target, schedule time zone, settings deep-link parsing). |
| BE service / adapters | `apps/agent-usage/server.mjs`, `state.mjs`, `usage.mjs`, `live-quota.mjs`, `launch-agents.mjs`, `scripts/`, `plugins/*/scripts` | HTTP, files, launchd, CLIs. `launch-agents.mjs` spawns `launchctl` only through an injectable runner. |
| Strings | `apps/agent-usage/ui/strings.mjs` | One English dictionary with parameterised formatters. Swift text stays inline. |
| Design tokens | `apps/agent-usage/ui/styles.css` `:root` blocks | Colours and the `--text-*` type scale. No hex or `font-size` outside them. |
| FE presentation | `apps/agent-usage/ui/dashboard.mjs`, `index.html`, `menubar/UsagePanel.swift`, `AgentUsageBar.swift`, `DashboardLink.swift` | Renders the view-model; no rules. The menu bar Settings button opens `#settings` (or `#settings/<general\|notifications\|accounts\|auto-route>`). |
| QA | `tests/*.test.mjs` (node:test, BE/FE-UT/BL/IT), `tests/fixtures/agent-usage/` (scenario data and fixture server), `tests/pages/` (page object), `tests/tests-web/` (Playwright), `tests/architecture-guard.test.mjs` | `npm test`, `npx playwright test`. The guard fails on rogue hex, raw font sizes, rules or fixed time zones in the dashboard, untagged or duplicate test ids, and a test that spawns `launchctl`. |

The `/api/quota` route decisions carry `routeStatus` (Off, Allowed, Diverted). The dashboard and menu bar derive it themselves when an older server omits it.

## Verification Invariants

- CLI binary detection must check `command -v agy` before attempting invocation.
- Subprocess exit codes must be captured and parsed; nonzero exits must output formatted stderr diagnostics.
- Hand-off is judged only by the repository's test command, run by the companion, never by agy's own claim; edited `--tests` files fail the run.
- Screenshots and documents produced by agy are checked by the host model (Claude reads the images); agy's own description of a page is not trusted.

## Structure deviations

- §1 one dir = one role (MUST) — `plugins/agy/` is the Claude Code plugin layout (commands, agents, hooks, prompts, scripts, skills) mandated by the plugin system, not the role layout — revisit only if the plugin spec changes.
